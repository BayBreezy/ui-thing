:prose-pm-x{command="ui-thing@latest"}

```sh
Usage: ui-thing [options] [command]

CLI for adding ui-thing components to your Nuxt application

Options:
  -V, --version                      output the version number
  -h, --help                         display help for command

Commands:
  init [options]                     Initialize UI Thing in your Nuxt project.
  add [options] [componentNames...]  Add a list of components to your project.
  registry                           Browse and configure shadcn-style component registries.
  block [options]                    Add UI Thing blocks to your project.
  theme [themeName]                  Add a new theme to your project.
  list [options]                     List available or installed components.
  update [componentNames...]         Re-fetch and overwrite installed components with the latest version.
  remove [componentNames...]         Remove installed components from your project.
  shortcuts                          Add the shortcuts composables to your project.
  prettier                           Adds prettier config to your project.
  help [command]                     display help for command
```

::prose-callout{variant="info" title="Looking for prose components?"}
Prose components for Nuxt Content (callouts, steps, tabs, code groups and more) now ship with [docd](https://github.com/BayBreezy/docd), a Nuxt layer for documentation sites. Run `npx create-docd my-docs` to start a project with all of them. The CLI no longer has a `prose` command.
::

## init

:prose-pm-x{command="ui-thing@latest init"}

This command will initialize UI Thing in your Nuxt project. This will:

- Install the core dependencies, including Tailwind CSS v4 and its Vite plugin
- Update your `nuxt.config` file (modules, color mode, icons, auto-imports and your Tailwind CSS file)
- Write your Tailwind CSS file with the theme you pick
- Add a `tw-helper.ts` util and merge recommended settings into `.vscode`
- Create a `ui-thing.config.ts` file with your answers
- Ask if you want to add a Prettier config

It is recommended that you run this command in a new Nuxt project before adding any components. See the [setup guide](/getting-started/setup) for the questions it asks.

```sh
Usage: ui-thing init [options]

Initialize UI Thing in your Nuxt project.

  ✅ Add tailwindcss to your project
  ✅ Update your nuxt.config file
  ✅ Add the necessary dependencies
  ✅ Create a ui-thing.config file with the default configuration

Options:
  -f --force                 Overwrite config file if it exists. (default: false)
  -y --yes                   Skip prompts and use default values. Detects your package manager and skips the Prettier question. (default: false)
  -n --nuxtVersion <number>  Specify the Nuxt version you are using.
  -h, --help                 display help for command
```

## add

:prose-pm-x{command="ui-thing@latest add"}

This command will add a list of components to your project. If no argument is passed, it will ask you to select from a list of available components.

```sh
? Select the components you want to add >
Instructions:
    ↑/↓: Highlight option
    ←/→/[space]: Toggle selection
    [a,b,c]/delete: Filter choices
    enter/return: Complete answer

Filtered results for: Enter something to filter

◯  Accordion
◯  Alert
◯  Alert Dialog
◯  ApexCharts
◯  Apexcharts
◯  Aspect Ratio
◯  Autocomplete
◯  Avatar
◯  Badge
◯  Border Beam
```

You can also pass the components you want by name:

:prose-pm-x{command="ui-thing@latest add button card dialog"}

For each component, the CLI copies its files into your components directory, adds any composables, utils and plugins it needs, adds required Nuxt modules to your `nuxt.config`, and asks before installing its dependencies.

```sh
Usage: ui-thing add [options] [componentNames...]

Add a list of components to your project.

Arguments:
  componentNames          Components to add. Accepts ui-thing names, registry URLs (https://.../r/item.json) or @namespace/item.

Options:
  -a --all                Add all components to your project. (default: false)
  --skip-config           Add components without a ui-thing config file. Uses auto-detected Nuxt defaults.
  --package-manager <pm>  Package manager to use when --skip-config is set.
  -y --yes                Skip confirmation prompts (uses yup for vee-validate components). (default: false)
  --validator <name>      Schema library to install for vee-validate components: yup, zod, joi or valibot.
  -h, --help              display help for command
```

- `--all` adds every component and installs their dependencies without asking.
- `--skip-config` lets you add components to a project that has no `ui-thing.config.ts`. The CLI uses defaults for your Nuxt version and asks which package manager you use, unless you pass `--package-manager`.
- `--yes` skips the confirmation prompts. Components that use vee-validate (`vee-input` and friends) need a schema library: with `--yes` the CLI installs yup.
- `--validator` picks the schema library for those components: `yup`, `zod`, `joi` or `valibot`.

### Registries

`add` can also install components from any shadcn-style registry (the `registry-item.json` format used by shadcn/ui and shadcn-vue). That means components from sites like [Vue Bits](https://vue-bits.dev) and [NXUI](https://nxui.geoql.in) can be added with one command instead of being converted by hand.

```sh
# the URL of a registry item
ui-thing add https://nxui.geoql.in/r/fluid-glass.json

# a namespaced item
ui-thing add @vue-bits/HoloMosaic

# skip the confirmation prompt
ui-thing add @nxui/fluid-glass --yes
```

`@vue-bits` and `@nxui` are built in. You can [add your own namespaces](#registry) below.

When you add a registry item, the CLI:

- Lists every file and package it is about to add and asks you to confirm. Registry items are code from someone else, so read the list before saying yes
- Places files using the folders in your `ui-thing.config.ts` (a registry's `components/ui/` folder becomes your components folder) and keeps any sub-folders
- Installs the item's npm dependencies, and any `registryDependencies` it lists, including other registry items
- Merges the item's `css`, `cssVars` and `envVars` into your Tailwind CSS file and `.env` without duplicating or overwriting what is already there
- Creates a `cn` helper (`clsx` and `tailwind-merge`) at `lib/utils.ts` in your source folder if the item imports `cn` from `~/lib/utils` and you don't have one
- Refuses to write outside your project

::prose-callout{variant="info" title="Server-side rendering"}
Some registry components use the browser (canvas, WebGL, `window`). If you see errors during server rendering, wrap the component in `<ClientOnly>`.
::

Every item you add from a registry is recorded in a `ui-thing.lock.json` file at the root of your project. `list --installed`, `update` and `remove` use it.

## registry

The registry command lets you browse registries and set up your own namespaces.

```sh
Usage: ui-thing registry [options] [command]

Browse and configure shadcn-style component registries.

Commands:
  list [source]                    List configured registries, or the items in one (@namespace or URL).
  search <query> [source]          Search registry items by name or description.
  add-namespace <namespace> <url>  Add a registry namespace to ui-thing.config.ts.
  help [command]                   display help for command
```

```sh
# show the registries you can use
ui-thing registry list

# list every item in a registry
ui-thing registry list @nxui

# search one registry, or all of them if you leave the namespace out
ui-thing registry search glass
ui-thing registry search holo @vue-bits

# add your own registry
ui-thing registry add-namespace @acme https://acme.dev/r/{name}.json
```

Namespaces are saved under `registries` in `ui-thing.config.ts`. The value is a URL template containing `{name}`. If the registry needs headers or query params, use an object instead. `${ENV_VAR}` references are replaced with your environment variables.

```ts [ui-thing.config.ts]
export default {
  // ...
  registries: {
    "@acme": "https://acme.dev/r/{name}.json",
    "@private": {
      url: "https://private.dev/r/{name}.json",
      headers: { Authorization: "Bearer ${PRIVATE_TOKEN}" },
    },
  },
};
```

Then add from it with `ui-thing add @acme/button`.

## block

:prose-pm-x{command="ui-thing@latest block"}

The block command adds larger, copy-paste page sections to your project. Run it with no arguments to pick a category and blocks from a list, or pass block names to add them directly. The default folder is `app/components/Blocks` for Nuxt 4 and `components/Blocks` for Nuxt 3.

The CLI also adds the UI Thing components a block uses and installs the npm packages it imports (for example `dayjs` or `@faker-js/faker`).

```sh
# browse
ui-thing block --list                      # categories and counts
ui-thing block --list --category pricing   # blocks in one category
ui-thing block --json --category hero      # machine-readable, for scripts and AI agents

# add by name (BlockHero1, "Hero 1" and hero-1 all work)
ui-thing block BlockHero1 BlockPricing2
ui-thing block BlockHero1 --dir app/components/Marketing --yes
```

With `--yes` nothing is asked: blocks go to the default folder (or `--dir`), existing files are skipped, and components and packages are installed. The CLI prints the tag to use for each block, such as `<BlocksHeroBlockHero1 />`.

```sh
Usage: ui-thing block [options] [blockNames...]

Add UI Thing blocks to your project.

Arguments:
  blockNames                Blocks to add, for example BlockHero1 or 'Hero 1'. Omit to pick interactively.

Options:
  -c --category <category>  Filter blocks by category
  -l --list                 List block categories, or the blocks in --category, and exit
  --json                    Print the block catalog (or one --category) as JSON and exit
  -d --dir <path>           Folder to write the blocks to (default: app/components/Blocks)
  -y --yes                  Skip all prompts: use the default folder, skip existing files, install components and packages
  -h, --help                display help for command
```

## theme

The theme command allows you to add a new theme to your project.

You can visit the [themes page](https://ui.shadcn.com/themes) on shadcn to see the available themes.

:prose-pm-x{command="ui-thing@latest theme"}

Running this command allows you to select a theme from the list

```sh
? Which theme do you want to add? »
>   Zinc
    Slate
    Stone
    Gray
    Neutral
    Red
    Rose
    Orange
    Green
  ↓ Blue
```

You can also pass the name of the theme, for example `ui-thing@latest theme rose`. The available themes are Zinc, Slate, Stone, Gray, Neutral, Red, Rose, Orange, Green, Blue, Yellow and Violet.

The CLI asks before overwriting your Tailwind CSS file, because adding a theme replaces its contents. Pass `--yes` to skip the question.

```sh
Usage: ui-thing theme [options] [themeName]

Add a new theme to your project.

Arguments:
  themeName   The name of the theme you would like to add

Options:
  -y --yes    Overwrite the Tailwind CSS file without asking. (default: false)
  -h, --help  display help for command
```

## list

:prose-pm-x{command="ui-thing@latest list"}

Lists the components you can add. Use `--installed` (or `-i`) to only show the ones already in your project, including items you added from a registry.

```sh
Usage: ui-thing list [options]

List available or installed components.

Options:
  -i --installed  Only show installed components. (default: false)
  -h, --help      display help for command
```

## update

:prose-pm-x{command="ui-thing@latest update"}

Re-fetches components and overwrites your copies with the latest version. Pass component names, or run it with no arguments to pick from the ones you have installed. Registry items are fetched again from the address recorded in `ui-thing.lock.json`.

::prose-callout{variant="warning" title="Your changes will be overwritten"}
The files are replaced without asking. If you edited a component, commit your work first so you can see what changed.
::

## remove

:prose-pm-x{command="ui-thing@latest remove"}

Removes components from your project. Pass component names, or run it with no arguments to pick from the ones you have installed. The CLI asks you to confirm first.

::prose-callout{variant="warning" title="Shared files"}
Removing a ui-thing component also removes the utils and composables it came with. Other components that use those files may stop working. Registry items only remove the files recorded in `ui-thing.lock.json`.
::

## prettier

The prettier command allows you to add an opinionated prettier config to your project.

:prose-pm-x{command="ui-thing@latest prettier"}

This will create a `.prettierrc` file that looks like this

```json
{
  "arrowParens": "always",
  "endOfLine": "lf",
  "plugins": ["@ianvs/prettier-plugin-sort-imports", "prettier-plugin-tailwindcss"],
  "printWidth": 100,
  "semi": true,
  "singleQuote": false,
  "tabWidth": 2,
  "trailingComma": "es5",
  "useTabs": false,
  "vueIndentScriptAndStyle": true,
  "tailwindFunctions": ["tv", "tw"],
  "importOrder": ["<BUILTIN_MODULES>", "<THIRD_PARTY_MODULES>", "<TYPES>", "", "^[.]"]
}
```

If you already have a `.prettierrc`, the CLI lets you merge the two, overwrite yours, or cancel. It then installs the necessary dev dependencies (`prettier`, `prettier-plugin-tailwindcss` and `@ianvs/prettier-plugin-sort-imports`).

This command does not reformat your files. Run `npx prettier --write .` when you want to. (If you accept the Prettier question during `init`, your code is formatted for you.)

## shortcuts

The shortcuts command allows you to add the `shortcuts` composables to your project.

:prose-pm-x{command="ui-thing@latest shortcuts"}

This will create a `shortcuts.ts` file in your `composables` directory and add the VueUse Nuxt module (`@vueuse/nuxt`) to your project.
